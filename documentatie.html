§01

Scop

Scriptul analizează acustic vocalizările bovine (viței și vaci) și înlocuiește un flux de lucru care înainte se făcea manual în Praat. Parcurge un director cu înregistrări, calculează parametrii acustici pentru fiecare vocalizare și scrie rezultatele într-un .csv (și, dacă e instalat openpyxl, un .xlsx).

Partea grea, care înainte se făcea de mână, era curățarea conturului de frecvență fundamentală (F0). În editorul de pitch din Praat, cineva trebuia să se uite la fiecare vocalizare și să scoată „săriturile” de urmărire — momentele în care algoritmul sare brusc la o octavă sau la o armonică și strică statisticile (exact secvența magenta din graficul de sus). Scriptul face asta automat (vezi §07). Manual, pasul dura mult și creștea odată cu numărul de vocalizări; automatizat, timpul total de extragere plus analiză a scăzut la aproximativ jumătate.

§02

Ce face, pe scurt

Pentru fiecare fișier audio, scriptul calculează:

  • Parametri de sursă (F0 / pitch): media, start/final, maxim, minim, interval, momentul maximului, panta absolută medie, variația și modulația de frecvență (FM rate, FM extent).
  • Energie spectrală: quartilele Q25/Q50/Q75 și frecvența de vârf (Fpeak).
  • Amplitudine (intensitate): AM var, AM rate, AM extent și durata sunetului.
  • Armonicitate (raportul armonic/zgomot, HNR).
  • Formanți (F1–F6 la viței, F1–F8 la vaci), dispersia formanților și lungimea estimată a tractului vocal.
  • Entropie Wiener (planeitatea spectrală).
  • (Opțional) Durata și ora vocalizării dintr-un fișier .tsv de adnotare.

Blocurile deterministe (Q25/Q50/Q75, Fpeak, durata, entropia Wiener) reproduc valorile de referință la nivel de rotunjire.

§03

Cerințe și instalare

Scriptul e folosit pe Windows, cu Python instalat global și pip, rulat din consola integrată din VS Code. Ar trebui să meargă la fel pe Linux/macOS — o rulare pe Linux din consola nativă, cu un venv, e planificată dar încă netestată.

Ai nevoie de Python 3.10 sau mai nou (folosit pe 3.12) și de pachetele din requirements.txt: 

pip install -r requirements.txt

sau, manual:

pip install praat-parselmouth "numpy>=2.4.4" pandas openpyxl

numpy e fixat la >=2.4.4 dintr-un motiv concret: pe 2.4.2, parselmouth dădea crash-uri native pe Windows care dispăreau pe 2.4.4. openpyxl e opțional — trebuie doar pentru exportul .xlsx; CSV-ul se scrie și fără el.

§04

Utilizare de bază

Scriptul procesează un director odată. Sunt suportate extensiile .wav, .aif, .aiff și .au, însă recomandarea puternică este .wav (formatul pe care a fost testat și validat scriptul).

Viței

python bovine_acoustics.py -i director -o rezultate.csv -a calf -c LFC

Vaci

python bovine_acoustics.py -i director -o rezultate.csv -a cow -c HFC
Notă despre -c -c/--call-type este obligatoriu la orice rulare (LFC sau HFC). La viței analiza folosește parametri ficși, dar -c este folosit oricum pentru a selecta tipul corect din fișierul .tsv (vezi §09) — deci treceți -c HFC chiar și pentru -a calf pe un folder HFC.

§07 · funcția centrală

Curățarea automată a anomaliilor F0

Algoritmul de urmărire a pitch-ului produce uneori „sărituri” bruște (la o octavă sau la o armonică superioară) care denaturează statisticile F0. În Praat, cercetătorul le elimina manual. Aici pasul este automat (filter_f0_outliers):

  1. Se extrage conturul F0 într-un vector NumPy (cadrele nevocale = NaN).
  2. Se calculează diferența dintre cadre consecutive: Δf = |F0[i] − F0[i−1]|.
  3. Se calculează o mediană glisantă ca „linie de bază” a frecvenței reale.
  4. Când apare o săritură ≥ --filter-jump (implicit 30 Hz) care duce valoarea la peste ~30 Hz distanță de linia de bază, se marchează începutul unei secvențe anormale.
  5. Se marchează întreaga secvență contiguă, până când urmărirea revine la linia de bază (în limita --filter-return-tol) sau se termină segmentul vocal.
  6. Cadrele marcate sunt eliminate; se construiește un PitchTier corectat, iar statisticile F0 și modulațiile se recalculează din el.

Detectarea se face pe conturul de pitch brut (înainte de netezire/interpolare), fiindcă acolo sunt vizibile săriturile — exact ca în fluxul manual Praat. Fișierele fără anomalii rămân identice cu rezultatul clasic. Filtrarea este activă implicit; se dezactivează cu --no-filter (util pentru reproducerea exactă a foilor de calcul vechi).

§08

Implementări duble: faithful vs experimental

Acolo unde macro-urile Praat conțin o particularitate matematică, scriptul oferă două variante (implicit faithful peste tot). faithful reproduce exact matematica Praat (identic cu foile istorice) — aceasta trebuie folosită. experimental este o versiune corectată matematic, dar încă nevalidată.

De reținut Variantele experimental trebuie validate de un expert din domeniu înainte de a fi folosite în analize. Până atunci, folosiți faithful.
--modulation-method

Modulație F0 / intensitate

faithful: reproduce bucla Praat, inclusiv particularitatea de indexare (limita din PitchTier, indexarea cadrelor), cu alinierea corectă 0-based ↔ 1-based.

experimental: variantă vectorizată pe tot conturul valid.

--wiener-method

Entropie Wiener

faithful: reproduce To Spectrum (dft) și particularitatea de indexare a matricei de putere (rezultat identic cu referința).

experimental: binii reali din bandă + medie geometrică corectă numeric (doar binii pozitivi).

--dispersion-method

Dispersia formanților

faithful: media distanțelor consecutive dintre formanți (formula telescopică Praat).

experimental: panta prin regresie liniară pe (indice formant, frecvență) — folosește toți formanții.

§09

Coloanele Duration(s) și Start

Dacă în directorul fișierului de ieșire există un fișier .tsv (numele nu contează — se caută primul *.tsv), scriptul adaugă la final două coloane preluate din el. Structura așteptată (separat prin TAB):

Sursa fișierului .tsv Acest fișier nu este creat de acest script — el este rezultatul unui alt script intern, aplicat direct în Praat, care exportă intervalele adnotate (momentul și durata fiecărei vocalizări). 
tmin      tier      text   tmax        tsec        Ora_Muget
9.265731  8_00_6    HFC    10.300537   1.034805... 08:41:29
...

Maparea

  • Se păstrează doar rândurile al căror text este de tipul rulării (LFC/HFC, dat de -c).
  • Al k-lea rând de acel tip (în ordinea din .tsv, cronologică) este asociat fișierului <TIP>_k după numărul din nume: primul HFC → HFC_1, al doilea → HFC_2…
  • tsec → Duration(s) (3 zecimale); Ora_Muget → Start (ora exactă, ex. 08:41:29).
Comportament robust Fără .tsv valid, cele două coloane sunt omise, motivul e afișat, iar rularea continuă. La nepotrivire de număr, rândurile fără corespondent primesc valori goale și se afișează un avertisment.
Cerință de numerotare Fișierele trebuie denumite <TIP>_<k> (ex. HFC_1.wav), unde k este ordinea vocalizării de acel tip. Doar așa asocierea cu .tsv este corectă.

§10

Rulare robustă pe mașini cu resurse limitate

Analiza folosește exclusiv CPU și RAM (Praat via parselmouth, plus NumPy/Pandas) — nu folosește placa video (GPU).

--isolate — izolarea fiecărui fișier

Rulează fiecare fișier într-un subproces separat care se închide la final: memoria este eliberată complet între fișiere, iar un fișier care blochează motorul (crash nativ) omoară doar propriul subproces, nu întreaga rulare. Recomandat pe laptop-uri cu RAM puțin.

--retries — recuperare după crash nativ

Unele fișiere pot provoca un crash nativ (access violation / segfault) în etapa de formanți din parselmouth. Crash-ul este nedeterminist (depinde de dispunerea memoriei procesului), deci reluarea analizei complete într-un proces nou reușește de obicei la o încercare ulterioară. Cu --isolate, scriptul reia analiza completă de până la --retries ori (implicit 10); doar dacă toate eșuează, salvează fișierul sărind etapa problematică (coloanele rămân --undefined--, iar Comment notează recuperarea). 

# timpul nu contează → recuperare cvasi-sigură cu formanți
python bovine_acoustics.py -i .\HFC\ -o rezultate.csv -a calf -c HFC --isolate --retries 50

--max-duration — protecție împotriva fișierelor lungi

Sare peste orice înregistrare mai lungă de N secunde, verificând durata din antetul .wav înainte de a o încărca în memorie.

§11

Depanare

  • --mem-report — memoria maximă per fișier (cu --isolate) sau cumulativă. Funcționează pe Windows, Linux și macOS.
  • --debug — urmărirea nativă completă (faulthandler) la crash. Implicit dezactivat: crash-urile sunt raportate pe o singură linie și reîncercate.
  • --skip-formants / --skip-wiener — sar peste o etapă nativă „grea”. Utile pentru a localiza etapa care provoacă un crash sau ca soluție de rezervă.
# dacă --skip-formants elimină crash-urile, cauza e etapa de formanți
python bovine_acoustics.py -i ... -o ... -a calf --isolate --skip-formants

§12

Validare față de referință

Am comparat ieșirea scriptului cu foi de calcul făcute de mână, folosind compare.py (descris la final). Referințele acoperă 1223 de vocalizări din 58 de înregistrări (în jur de 29 de ore de audio), grupate în 30 de sesiuni. Un lucru de ținut minte când citești cifrele: fiecare set de referință a fost făcut de altă persoană, iar pasul manual din Praat — mai ales unvoicing-ul — presupune decizii subiective. Deci o parte din diferențe vine din cum a lucrat fiecare adnotator, nu doar din script. Nu putem separa complet cele două, dar structura erorilor de mai jos arată destul de clar unde se întâmplă.

Pe ansamblu, 95% din cele ~35.000 de valori numerice cad în ±5% față de referință (pragul pe care îl folosim ca „potrivire”; în proiect, peste 90% pe o sesiune înseamnă succes). 25 din 30 de sesiuni trec de 90%, iar 16 sunt peste 98%.

Acuratețea pe fiecare sesiune (procentul de valori în ±5% față de referință).

Sesiunile nu sunt uniforme — cele mai multe stau sus, câteva pică. Cele care pică sunt aceleași seturi de referință în care și diferențele pe F0 sunt cele mai mari (vezi mai jos), adică exact acolo unde adnotatorii au avut cel mai mult loc de interpretare.

Diferențele nu sunt împrăștiate uniform peste parametri, ci strânse într-un singur grup:

Eroarea relativă medie pe parametru, agregată pe toate cele 3 seturi.

Parametrii calculați direct din semnal — quartilele spectrale (Q25/Q50/Q75), Fpeak, durata, amplitudinea (AM), armonicitatea — și formanții (F1–F6, dispersie, VTL) coincid cu referința sub ~1% eroare relativă. Aceștia nu depind de conturul de pitch, deci nici de deciziile de unvoicing.

Aproape toată diferența vine din parametrii de F0 și modulație: FM Extent, Time max F0, F0 var, FM Rate, Range F0, panta absolută. Toți se calculează din conturul de pitch și din ce cadre sunt scoase — adică fix partea subiectivă a procesului manual. Unde adnotatorii au ales diferit, aici se vede.

Două cifre din grafic trebuie citite cu grijă, ca să nu ducă în eroare. FM Extent iese cel mai sus pentru că e un raport cu numitor mic (variația totală împărțită la numărul de cicluri de modulație): o diferență mică în valoare absolută devine mare în procente. Iar mean wiener entropy urcă doar în câteva sesiuni, unde valoarea e aproape de zero și orice diferență mică se amplifică relativ.

compare.py

compare.py compară un fișier de ieșire cu o foaie de referință și raportează, pe fiecare coloană, eroarea medie/maximă și procentul de valori în toleranță. 

python compare.py -orig referinta.csv -new rezultate.csv -t 0.05 -r 0.01
  • -t — toleranță absolută (în unitățile coloanei).
  • -r, --rel-tolerance — toleranță relativă (ex. 0.01 = 1%). E utilă fiindcă tabelul are coloane de scări foarte diferite (F0 ~80 Hz vs formanți ~3000 Hz); o valoare trece dacă e în toleranța absolută sau în cea relativă.
  • Median_Rel_Err — eroarea relativă mediană pe coloană.

§14

Note și limitări cunoscute

  • Formanții pot diferi cu sub-Hz față de Praat, fiindcă parselmouth și Praat folosesc implementări interne diferite ale algoritmului Burg/LPC. Nu e o eroare de traducere, ci o diferență de motor.
  • Statisticile F0 pe fișierele marcate manual nu pot fi reproduse exact: pasul manual de „unvoicing” din Praat este subiectiv, iar coloana Comment din referință e text liber.
  • Blocurile deterministe (Q25/Q50/Q75, Fpeak, durata, AM rate, entropia Wiener) reproduc referința la ~1e-3.
  • Crash-urile native în etapa de formanți (0xC0000005 pe Windows) sunt o problemă a bibliotecii parselmouth/Praat, gestionată prin izolare și reîncercări — nu o problemă de memorie.

§15 · referință tehnică

Pentru developeri

Scriptul este un singur modul, bovine_acoustics.py, fără stare globală: totul se transmite prin argumente, astfel încât aceeași funcție de analiză rulează identic în proces sau într-un subproces izolat.

Fluxul de execuție

Sound→ To Pitch (cc)→ _f0_block · filtrare F0→ Energie→ Intensitate→ Armonicitate→ Formanți→ Wiener→ rând CSV

main() parsează argumentele și cheamă process_directory(), care listează fișierele și, pentru fiecare, apelează _analyze_one() — direct, sau (cu --isolate) prin _run_resilient() → _run_isolated() într-un subproces spawn. Rezultatele se agregă într-o listă de dicționare, se mapează coloanele din .tsv (_add_timestamp_columns) și se scrie CSV-ul (plus XLSX-ul regenerat din CSV).

Harta funcțiilor

analiză per fișier

Pipeline & metrici

analyze_calf / analyze_cow — pipeline-ul complet; fiecare obiect Praat este eliberat imediat ce a fost citit (memorie minimă).

_f0_block — statistici F0 din pitch-ul netezit; aplică apply_f0_filter pe pitch-ul brut; recalcul din PitchTier-ul filtrat.

filter_f0_outliers, extract_energy_parameters, și perechile calculate_*_faithful / calculate_*_experimental (modulație, Wiener, dispersie), fiecare cu un dispecer get_*.

infrastructură

Robustețe, I/O, format

_run_isolated (subproces + Queue), _run_resilient (scara de reîncercări), _describe_exit (cod ieșire → cauză), _peak_rss_mb (Unix resource + Windows ctypes), _probe_duration.

praat_format (regulile :N, --undefined--), constantele CALF_PRECISION/COW_PRECISION și CALF_HEADER/COW_HEADER.

_load_tsv_timestamps, _file_index, _add_timestamp_columns pentru coloanele din .tsv.

Cum adaugi o metrică nouă

  1. Calculeaz-o în analyze_calf/analyze_cow și pune valoarea în dicționarul returnat, cu o cheie clară.
  2. Adaugă aceeași cheie în CALF_PRECISION/COW_PRECISION (numărul de zecimale, sau None pentru precizie completă).
  3. Adaugă eticheta în constanta de antet CALF_HEADER/COW_HEADER. Cheia din dicționar trebuie să fie egală cu eticheta de antet fără spațiile din față (potrivirea se face pe numele „trimmed”).

Cum adaugi o variantă experimental

Urmează tiparul existent: calculate_[metric]_faithful + calculate_[metric]_experimental + un dispecer get_[metric](method, ...), apoi un argument CLI --[metric]-method transmis prin dicționarul methods.

Note tehnice utile
  • Indexare: cadrele Praat sunt 1-based, vectorii NumPy 0-based — cadrul Praat f ↔ values[f-1]. Vezi comentariile din funcțiile de modulație și Wiener.
  • Subprocese: contextul este spawn (curat, portabil). Modulul trebuie să rămână importabil fără efecte secundare (păstrează garda if __name__ == "__main__").
  • Un crash nativ nu poate fi prins în proces — de aceea izolarea + reîncercările sunt singura cale de recuperare.
  • De ce numpy fixat: ABI-ul dintre parselmouth și NumPy — un patch de NumPy poate declanșa/opri crash-urile native.
